# OctoForge

Мультипользовательский LLM-агент: скилы на Jinja-DSL, знания в БД, фоновые задачи.
Дизайн — в [docs/design.md](docs/design.md), конвенции кода — в [AGENTS.md](AGENTS.md).

## Структура репозитория

Монорепо из двух независимых Python-проектов:

- `core/` — библиотека `octoforge-core`: домен, порты, сервисы, клиенты LLM. Свои зависимости и тесты.
- `web/` — приложение `octoforge-web`: FastAPI-обёртка над библиотекой, чат-UI. Свои зависимости и тесты.

## Быстрый старт

```bash
make install          # создать .venv и поставить оба проекта (editable, с dev-зависимостями)
cp .env.example .env  # заполнить OF_LLM_API_KEY и при необходимости OF_LLM_BASE_URL / OF_LLM_MODEL
make run              # uvicorn с автоперезагрузкой
```

Открыть http://127.0.0.1:8000 — чат с LLM. Поле «Как вас зовут?» задаёт имя,
которое попадает в приветствие и в системный промпт.

## Проверки

```bash
make check  # ruff (lint + format) → mypy → pytest для обоих проектов
```

Отдельно: `make lint`, `make typecheck`, `make test`, `make format`.

## Текущий статус

Реализовано (этапы A–F из [docs/plan.md](docs/plan.md)):

- чат без аутентификации: `user_id` — доверенная строка (заголовок `X-User-Id`, в UI — поле имени);
- персист диалогов, сообщений и задач в SQLite; изоляция по `(user_id, channel)`, история переживает рестарт;
- агентная петля со стримом токенов и отменой; процессная модель (фон/форграунд) с LLM-роутером входящих сообщений;
- инструкции в БД (знания/скилы/тулы) с векторным поиском, `external_call` с SSRF-гвардом, сид примеров (wttr.in, крон-тулы);
- датасеты пользовательских данных (`data_put`/`data_query`/`data_forget`), память (`memory_store`/`memory_search`/`memory_delete`);
- крон-задачи: HTTP API `/api/cron/*`, планировщик с CAS-арендой, создание задач агентом через `external_call`.

Для инструкций и датасетов нужны эмбеддинги: локальный бэкенд sentence-transformers
(`OF_EMBEDDING_BACKEND=local`, модели из Hugging Face-кэша, опциональный кросс-энкодер
реранкер `OF_RERANKER_MODEL`) или OpenAI-совместимый эндпоинт. Без рабочего бэкенда
приложение стартует (сидирование пропускается), но поиск/сохранение инструкций и
создание датасетов недоступны.

Дальше по плану: аутентификация, Telegram-адаптер, редоставка результатов задач после
рестарта, eager tool execution — см. «Дальше» в [docs/plan.md](docs/plan.md).
