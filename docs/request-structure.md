# Структура запроса к LLM основного прогона

> Собрано по коду на 2026-07-21: сборка ветки — `core/src/octoforge_core/agent/runner.py`
> (`_start_new`), отправка — `agent/loop.py` (`stream(history, tools=registry.specs())`).
> Размеры замерены скриптом на текущих текстах; токены — оценка 4 chars/токен (тот же
> прокси, что у `CompactorConfig`).
>
> Пре-поиск **отменён решением от 2026-07-21** (см. `docs/instructions.md`, раздел
> «Пре-поиск скилов до прогона») — строка 2 таблицы исчезнет вместе с кодом.

## Порядок сборки

Массив `messages` ветки процесса:

```
[0] system    — системный промпт + строка с текущей датой UTC
[1] system    — заметка пре-поиска скилов (опционально; отменена, подлежит удалению)
[2] system    — блок саммари прошлых тем (опционально)
[3..] user/assistant/tool — «горячий хвост» переписки дословно,
      вперемешку со служебными system-заметками; замыкается trail-сообщением
```

Поле `tools` запроса (не сообщение) — спеки всех тулов, отправляется на КАЖДОЙ итерации
петли: после исполнения тулов весь массив + схема уходят в LLM заново.

## Таблица частей

| Порядок | Часть | Тип(ы) сообщений | Состав | Размер | ~Токены |
|---|---|---|---|---|---|
| 0 (отдельное поле) | Тулы, 19 шт. | не сообщение — поле `tools` | JSON-спеки cron×5, memory×3, data×3, history_search, task×2, web_search, http_request, external_call, skills_search, instruction_save | 10 670 chars | ~2 670 |
| 1 | Системный промпт | `system` (всегда первый) | `DEFAULT_SYSTEM_PROMPT` (5 мета-правил) + текущая дата UTC | ~950 chars | ~240 |
| 2 | Заметка пре-поиска (отменена) | `system` (опционально) | до 3 скилов с полными текстами + однострочные ссылки на knowledge/endpoint; ветка-only, не персистится | 0 – ~3 000 chars | 0 – ~750 |
| 3 | Блок тем | `system` (одно сообщение, опционально) | все саммари диалога склейкой: `[seq N-M] (topics: ...) текст` | 0, растёт с возрастом диалога | — |
| 4 | Горячий хвост | `user` / `assistant` / `tool` + `system`-заметки | дословная переписка `seq > max(seq_to)`: сообщения пользователя, финалы и промежуточные ответы модели (с `tool_calls`), результаты тулов (с `tool_call_id`) | ≤ 12 000 chars (`OF_CONTEXT_HOT_MAX_CHARS`) | ≤ ~3 000 |
| 4а | Служебные заметки | `system` | `INTERRUPTED_NOTE` (71 char), уведомления «фоновая задача завершена» | десятки–сотни chars | — |
| 5 | Trail / репорт-надж / инъекции | `user` | входящее сообщение процесса; `REPORT_NUDGE` в репорт-прогоне; инъекции роутера через `LoopControl` | — | — |

Самые тяжёлые тулы: `history_search` ~250 ток, `cron_create` и `data_put` ~245 ток,
`data_query` ~220 ток, `memory_store` ~190 ток; мелкие (`cron_list`, `task_list`) — ~50 ток.

## Итоги

- Постоянный «налог» каждой итерации: системный промпт + тулы ≈ 11 600 chars / ~2 900 ток.
- Переменная часть: пре-поиск (пока жив) + хвост ≈ до ~15 000 chars / ~3 700 ток;
  переполнение хвоста уходит в саммари фоновой компакцией (цель 6 000 chars,
  `OF_CONTEXT_COMPACT_TARGET_CHARS`).
- Типичный запрос диалога: ~12–25 тыс. chars / ~3–6 тыс. токенов.

## Соседние запросы (не основной прогон)

- **Роутер** (`LLMRouter`, на каждое входящее сообщение): `system` — роутерный промпт
  (~1 365 chars / ~340 ток) + список активных процессов, `user` — входящее сообщение,
  тул `route` в поле `tools`. One-shot `complete()`.
- **Фоновый процесс** (`task_spawn`, крон-выстрел): ветка начинается с `system`
  (`BACKGROUND_TASK_PROMPT` + дата, ~100 chars) + `user` (промпт задачи), дальше тот же
  шаблон, что у основного прогона.
- **Компакция** (фоновая, не процесс): `system` — `SUMMARY_SYSTEM_PROMPT`, `user` —
  сегмент архива. One-shot `complete()`.

## Роли в хвосте: assistant vs tool

- `assistant` — слова модели: промежуточное сообщение с `tool_calls` («вызови тулы»,
  прогон продолжается) или финал без `tool_calls` (ответ пользователю, прогон кончился).
- `tool` — результат исполнения скила, привязан к вызову через `tool_call_id`; за
  assistant с N `tool_calls` обязаны идти ровно N tool-сообщений (отменённый вызов
  получает заглушку `CANCELLED_OUTPUT` — парность не нарушается). Ошибки скилов тоже
  возвращаются tool-сообщением с префиксом ошибки, а не исключением.
