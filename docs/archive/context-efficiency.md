# Экономия контекста: очистка ответов инструментов (HTTP и не только)

> **Статус: исследование, реализация позже.** Как уменьшить потребление токенов/контекста от
> ответов инструментов (`http_request`, `external_call`, `web_search`) без потери релевантной
> информации. Связанные доки: [design.md](design.md), [streaming.md](streaming.md),
> [modularity.md](modularity.md), [quality-audit.md](quality-audit.md), [data-store.md](data-store.md).

## Проблема

Ответы HTTP-инструментов (веб-страницы, JSON API) целиком попадают в ветку истории, которую агент
скармливает LLM на каждой итерации процесса. Сырой HTML/большой JSON раздувает контекст: растёт
стоимость и латентность, вытесняется полезное, быстрее упираемся в лимит окна. Сейчас в ядре
ответы режутся **по символам** (грубый cap в `http_request`/`external_call`) — это теряет смысл и
всё равно оставляет много «шума».

**Важная оговорка про «без потерь».** Полностью lossless для LLM почти не бывает (сжатие, которое
модель не может прочитать, бесполезно). Реальная цель — *без потери релевантной для задачи
информации*. В этом смысле уменьшение возможно и существенное.

## Практики (от самых безопасных к агрессивным)

### Практически lossless — убираем шум, не смысл

1. **Извлечение контента из HTML.** Выкинуть скрипты/стили/навигацию/рекламу/разметку, оставить
   основной текст. Инструменты: `trafilatura`, `readability-lxml`, Mozilla Readability. Для
   веб-страниц часто −80…95% токенов почти без потери смысла.
2. **HTML → Markdown.** Сохраняет структуру (заголовки, списки, ссылки, таблицы), но в разы дешевле
   сырого HTML.
3. **Проекция полей для JSON/API.** Вместо всего ответа — только нужные поля (`jq`/JMESPath:
   `.items[].{id,title}`), без `null`, метаданных и пагинационного мусора. Near-lossless по нужным
   данным.
4. **Токен-осознанная обрезка.** Резать по токенам, а не символам, и брать **голову+хвост** (у API
   ошибки/итоги часто в конце), а не только начало.

### Мощно, но с потерями / доп. стоимостью

5. **Query-focused extraction (RAG-style).** В контекст класть только чанки ответа, релевантные
   текущему запросу (эмбеддинги/ранжирование — у нас уже есть `EmbeddingClient`). Теряется
   нерелевантное — обычно это и хорошо.
6. **Context offloading + ссылка.** Полный ответ сохранить в стор (`datasets`/scratchpad), в контекст
   положить короткое резюме + хэндл; агент дочитывает нужное по требованию отдельным тулом
   (`read_more`/`query`). По данным это lossless — они просто вне «горячего» контекста. Тот же приём
   у MCP (tool возвращает summary + resource link) и у Claude Code (читает *фрагменты* файлов).
7. **Суммаризация дешёвой моделью / sub-agent digest.** Саб-агент «переваривает» ответ и возвращает
   только выводы. Сильное сжатие, но **lossy**, +1 LLM-вызов (стоимость/латентность) и место для
   ошибок и **prompt-injection** (недоверенный контент, залитый через резюме).

### Ещё

- Дедупликация повторов, минификация (whitespace/base64-блобы/трекинг-параметры), кэш очищенных
  ответов.

## Применительно к OctoForge

Разумный апгрейд без переписывания ядра (ложится на порты из [modularity.md](modularity.md)):

- **`http_request`:** HTML→markdown-экстракция + токен-aware cap (голова+хвост) вместо символьного
  среза. Экстрактор — за портом (инсталлятор подменяет readability/trafilatura/свой).
- **`external_call`:** у тулов уже есть **декларированные параметры**; по аналогии декларировать
  **нужные поля ответа** (проекция в записи tool'а) — в контекст идёт только проекция.
- **Большие payload'ы:** offload в `datasets` + ссылка в нарратив, с тулом дочитывания.
- **Слой per-run branch:** durable/transient у нас уже есть на персисте (дельты транзиентны,
  персистятся только финалы — [design.md](design.md)); добавить аналогичный trimming ответов
  инструментов в ветке, которая скармливается LLM внутри процесса.

## Осторожно

- **JS-страницы:** очистка ломает контент, которого нет в исходном HTML — нужен fallback.
- **Безопасность:** любая очистка/суммаризация недоверенного веб-контента — это ещё и граница
  prompt-injection (см. [quality-audit.md](quality-audit.md), P2); сохраняйте provenance.
- **Стоимость:** суммаризация-вторым-вызовом добавляет стоимость/латентность — кэшируйте.
