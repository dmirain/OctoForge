# Процессная модель диалога и LLM-роутер

> **Статус: заменён (28.07.2026).** Актуальное описание ядра диалога —
> [exchanges.md](exchanges.md); конспект — в `design.md` («Актор диалога»,
> «Роутер сообщений»).

Описанная здесь модель (форграунд/фон, пакеты операций роутера INJECT/START_NEW/CANCEL,
разметка веток конвертами, requeue по водяной метке, гейт доставки «когда форграунд
свободен») заменена **моделью обменов**: durable-обязательство перед пользователем
(таблица `exchanges` + `messages.exchange_id`, статусы OPEN → IN_PROGRESS →
ANSWERED / AWAITING_USER / CANCELLED / FAILED), роутер решает NEW / CONTINUE / COMMAND
над живыми обменами, ветка рендерится одним правилом из durable-состояния
(`agent/branch.py`), каждый answer-прогон стримит в своё per-exchange сообщение, а
`ask_user` паркует обмен в AWAITING_USER до реплики пользователя. Что осталось от этой
модели: пул процессов, подкреплённых задачами (`process.id == task.id`, kind ANSWER/RUN),
pull-модель ветки и outbox как гарантия «нет подписчика — не теряем результат».

Файл сохранён как исторический указатель; содержимое не поддерживается.
